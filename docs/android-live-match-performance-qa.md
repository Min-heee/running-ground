# Android Live Match Performance QA

Android 대결 화면 렉을 비교할 때는 개발 빌드에서 `대결 보기` 카드 안의 `ANDROID QA PERF` 패널을 확인합니다.

## 패널 값

- `FPS`: 최근 5초 동안의 대략적인 화면 frame 수입니다.
- `평균 FPS`: 현재 대결 화면에서 쌓인 샘플 평균입니다.
- `렌더`: 최근 5초 동안 `LiveMatchArena`가 다시 렌더링된 횟수입니다.
- `평균 렌더`: 현재 대결 화면 샘플의 평균 렌더 횟수입니다.
- `변화 전체`: 최근 5초 동안 전체 참가자 progress/페이스/상태 표시값이 바뀐 횟수입니다.
- `표시`: `변화 전체` 줄에서는 실제 화면에 보이는 참가자의 표시값이 바뀐 횟수입니다.
- `숨은`: Android 경량 모드에서 화면에 보이지 않는 참가자 데이터만 바뀌었는데 카드 렌더가 발생한 횟수입니다.
- `정적`: 표시값 변화 없이 다시 렌더된 횟수입니다. 이 값이 높으면 부모 상태 또는 prop 생성 흐름을 봐야 합니다.
- `레이아웃`: 참가자 수, 표시 참가자 수, 대결 모드가 바뀐 횟수입니다.
- `거리`: 목표 거리 설정 변경으로 렌더된 횟수입니다.
- `진단`: 최근 샘플 기준으로 가장 의심되는 렉 원인을 요약합니다.
- `조치`: 진단에 맞춰 다음에 손봐야 할 코드 방향을 짧게 보여줍니다.
- `참가`: 전체 참가자 수입니다.
- `표시`: Android 경량 모드에서 실제 화면에 렌더링하는 참가자 수입니다.
- `샘플`: 5초 단위로 누적된 QA 샘플 수입니다.

## 테스트 방법

1. Android 개발 빌드에서 파티런 1대1을 시작합니다.
2. 카운트다운 후 `대결 보기` 화면에 들어가서 10초 이상 둡니다.
3. `FPS`, `렌더`, `변화 전체`, `표시`, `숨은`, `정적`, `진단` 값을 기록합니다.
4. 같은 방식을 iOS 또는 다른 Android 기기와 비교합니다.
5. 그룹 30명 테스트에서는 `참가 30명`, `표시 N명`이 보이는지 확인합니다.

## 판단 기준

- FPS가 45 이상이면 대체로 양호합니다.
- FPS가 30 근처로 떨어지면 화면 렌더링 또는 리스트 렌더링이 무거운 상태입니다.
- `렌더`가 5초에 10회 이상이면 상태 업데이트가 너무 자주 화면까지 내려오는지 확인합니다.
- `숨은`이 높으면 화면에 보이지 않는 참가자 progress까지 상위 카드 렌더를 밀어 올리는 상태입니다.
- `정적`이 높으면 데이터 변화가 없는데도 부모 컴포넌트가 새 props를 만들거나 화면 전환 상태가 흔들리는 상태입니다.
- `진단`이 `숨은 참가자 갱신 과다`이면 화면 밖 참가자 progress가 상위 카드 렌더를 흔드는 상태입니다.
- `진단`이 `정적 재렌더 과다`이면 데이터 변화 없이 부모 화면이 다시 그려지는 상태입니다.
- `진단`이 `FPS 저하 + 렌더 과다`이면 먼저 참가자 표시 수와 progress 갱신 주기를 줄이는 쪽을 봅니다.
- `참가`는 많은데 `표시`가 낮게 유지되면 Android 경량 모드가 정상 작동 중입니다.

## 로그 위치

- 화면 패널: `LiveMatchArena` 카드 안 `ANDROID QA PERF`
- 콘솔 로그: `[LiveMatchPerf] duel-arena ... progress=... visibleProgress=... hiddenProgress=... static=...`
- 메모리 QA 로그: `src/components/matches/liveMatchPerfQaLog.ts`
