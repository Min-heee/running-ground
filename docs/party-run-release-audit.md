# 파티런 출시 전 점검 메모

작성일: 2026-05-08

## 이번 코드 점검에서 잡은 문제

- 파티런 방장이 시작했을 때 서버가 모든 참가자를 즉시 `카운트다운 준비됨`으로 처리하고 있었습니다. 이제 방장만 즉시 준비 처리하고, 참가자 앱이 방 상태를 받은 뒤 ACK를 보내면 모두 준비된 시점부터 30초 카운트다운으로 맞춥니다.
- 파티런/그룹 대결 참가자가 실제 기록을 보내지 않았는데도 평균 페이스만으로 거리와 순위가 움직일 수 있었습니다. 이제 실제 live progress가 없는 참가자는 0km/측정 대기로 남기고, 테스트봇은 서버의 synthetic live snapshot으로만 움직입니다.
- 파티런 방이 실제 대결과 연결된 뒤에도 10분이 지나면 오래된 방처럼 정리될 수 있었습니다. 연결된 대결/진행 중 방은 active TTL을 사용해 장거리 러닝 중에도 유지되도록 했습니다.
- 1대1 대결에서 상대가 기권했는데 내 결과 계산이 상대 평균 페이스 추정값에 영향을 받을 수 있었습니다. 이제 상대 기권은 명확히 `상대 기권 승`으로 기록됩니다.
- 순위보기 placeholder에서도 기권 참가자가 위에 남을 수 있었습니다. 이제 기권 참가자는 아래로 정렬됩니다.
- 린트 설정이 없어 `npm run lint` 자체가 실패했습니다. Expo ESLint flat config를 추가했고, 에러는 0개로 맞췄습니다.
- Postgres 친구/리그 테스트가 실제 날짜에 의존해 시간이 지나면 깨지는 구조였습니다. 테스트 기준 날짜를 고정했습니다.
- production 앱 환경 검증이 Tailnet 내부 주소(`.ts.net`)도 통과시키고 있었습니다. 이제 production에서는 공개 API 도메인이 아니면 실패합니다.

## 실제 기기 QA 체크리스트

- iOS 방장 + Android 참가자로 파티런 1대1 방을 만들고, 참가자가 준비 완료를 누른 뒤 방장이 시작합니다.
- 시작 직후 두 기기 모두 로딩중 화면이 뜨고, 한쪽만 먼저 카운트다운으로 넘어가지 않는지 확인합니다.
- 카운트다운이 뜨면 두 기기의 숫자가 1초 이내로 맞는지 확인합니다.
- 20초 시점에 두 기기 모두 러닝 탭이 아니라 대결 보기 화면으로 넘어가는지 확인합니다.
- 카운트다운 종료 후 두 기기 모두 시간, 거리, 평균 페이스가 증가하는지 확인합니다.
- 대결 보기에서 내 페이스와 상대 페이스가 각각 평균 페이스 기준으로 갱신되는지 확인합니다.
- 순위 보기에서 두 명 모두 보이고, 더 많이 간 사람이 위에 뜨는지 확인합니다.
- 한 명이 기권하면 기권한 기기는 기록 저장 후 대결 화면에서 빠져나가는지 확인합니다.
- 상대 기기에서는 기권한 참가자 동그라미/순위 행이 빨간 기권 상태로 바뀌는지 확인합니다.
- 그룹 파티런도 같은 흐름으로 3명 이상에서 카운트다운, 대결 보기, 순위 보기, 기권 상태가 유지되는지 확인합니다.

## 남은 주의점

- 실제 GPS 품질은 실내 정지 테스트로는 검증할 수 없습니다. 최소 200m 이상 야외 이동 테스트가 필요합니다.
- `npm run lint`는 에러 0개지만 warning은 남아 있습니다. 출시 차단 수준은 아니지만, 다음 정리 작업에서 미사용 변수와 Hook dependency 경고를 줄이면 좋습니다.
- production API smoke는 통과했지만, 앱 OTA나 네이티브 빌드에 반영하려면 커밋/푸시 후 EAS Update 또는 빌드를 별도로 진행해야 합니다.
